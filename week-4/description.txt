For Week 4 of the Frontend Web Developer Intern program, I improved the performance and accessibility of my existing Launchpad Journal webpage. The project continues the responsive HTML, CSS, and JavaScript work from the earlier weeks while preserving its note search, topic filtering, saved reading list, field guide, and learning-plan form.

I first analyzed the original page using Lighthouse, axe, source inspection, and keyboard checks. The baseline already received excellent automated scores, but it still loaded unminified delivery files and showed a small mobile header layout shift. I introduced a reproducible optimization build, consolidated shared styling rules, optimized the local SVG illustrations, prioritized the hero image, and retained deferred JavaScript and lazy loading for lower images. The completed page files are 12.5% smaller. Three local mobile Lighthouse runs recorded zero layout shift after the changes, compared with 0.059 for the baseline, while maintaining 100 performance and accessibility scores.

For accessibility, I added a named search region, labelled the planning form, strengthened input borders and placeholder contrast, and improved keyboard focus movement. The skip link focuses the main content, mobile navigation moves focus to the selected section, and resizing recovers focus from hidden navigation controls. I also checked reduced-motion and forced-colors preferences and fixed text wrapping at increased text size.

Validation includes eight logic tests, twelve browser workflow groups, ten viewport widths, and ten additional accessibility and performance checks. Axe reported zero violations across the tested form and navigation states. The report includes measured results, implementation decisions, contrast ratios, screenshots, reproduction instructions, and the limits of automated testing. All results are local Chromium lab measurements; manual screen-reader and cross-browser reviews remain future checks.
