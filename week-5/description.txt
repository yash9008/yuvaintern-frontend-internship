For Week 5 of the Frontend Web Developer Intern program, I turned my existing Launchpad Journal webpage into a small single-page application. The project continues the work from the earlier weeks on purpose: the responsive layout, note search, topic filters, saved reading list, field guide and learning plan all still behave as before, but they now live in four routed views that the browser navigates without ever reloading the page.

I built the routing on a hash-based design so it works the same way from a local file, a local server, and GitHub Pages. Every in-app navigation changes the address bar and creates a real browser history entry, so the back and forward buttons move between views exactly as they would on a multi-page website, all inside one document. Search and filter changes rewrite the current history entry with a debounced URL update instead of adding entries, which keeps one typing session equal to one history record. Deep links such as /#/guide/layout open the view, expand the requested note, and move keyboard focus into it; unknown addresses render a not-found view, and the anchor links from my earlier weeks still resolve to their new routes.

View content loads on demand from two separate data files, keeping the first visit light. Loading is treated as a designed state: failures produce an accessible error message naming the missing file with a working retry path, which I verified by blocking the request in the browser suite. Scroll positions are saved per history entry and restored on back navigation, including waiting for asynchronously-loaded lists to be tall enough. The view transition is a 240 ms fade, disabled under prefers-reduced-motion.

Measurement kept me honest about the trade-off. The Lighthouse baseline from Week 4 scores 100 in every category with a 0.752-second paint; the SPA holds 100 in accessibility, best practices and SEO, scores 95 to 100 in performance, and paints in the same 0.751 seconds, though the client-rendered hero illustration enlarges the Largest Contentful Paint to 1.351 seconds and can produce a 0.138 layout shift when the illustration enters after first paint. The payload grows by about 11.4 kilobytes, which is the routing, URL state and loading code the page genuinely did not have before.

Verification includes fifteen routing and state logic tests, sixteen browser workflow groups with ten viewport widths, twelve accessibility check groups with five axe scans, and three Lighthouse runs against the same Week 3 baseline, all with zero page errors and zero axe violations. The report records the measurements, the design decisions, and the honest limitations such as lab-only timing and the JavaScript-built views.
